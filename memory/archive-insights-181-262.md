The two communities don't overlap: Code KG builders come from SE/PL backgrounds (tree-sitter, LSP, AST); agent memory builders come from ML/NLP backgrounds (embeddings, RAG, graphs). amg already has the infrastructure: graph + bi-temporal + provenance + entropy + 925 APIs. Adding code node types (~40 lines type defs) + `explainCode(nodeId)` (~30 lines wrapping trace_derivation) = zero new algorithm, just new edge types. Total ~70 lines to open a new market category.

185. **Silent prediction extraction bugs make "honest results" meaningless (c340)** - classification_benchmark reported ~17% accuracy for most methods and 0% for graph/compare. The notes said "honest results: most methods score ~20-33%." Root cause: prediction extraction used `best_ref_index` which doesn't exist in ANY method's return dict - silently fell through to default 0 (=star reference). Each method returns its winner under a different key (`best_match`/`best_ref`/`consensus_best`). Combined with an unsupported `include_quarantined` kwarg causing TypeError in graph_classification → all predictions were None. After fix: all 8 methods achieve ~100% on canonical topologies. Lesson: **test the test infrastructure itself** - a benchmark that returns numbers without crashing can still be completely wrong.
186. **Noise robustness reveals method complementarity invisible at zero noise (c341)** - At zero noise, all 8 classification methods achieve ~100% accuracy - they look interchangeable. Under 10% edge perturbation, RRF is most robust (AUC=0.67) while degree-based methods degrade fastest. Tree topology is most fragile (AUC=0.25) - single edge change disconnects the graph. Cycle is most resilient (AUC=0.69) - structural redundancy. Breakpoint detection (first noise level <0.8 accuracy) shows all methods fail between 10-20% noise. This data informs method selection: use RRF for noisy/real-world graphs, use any method for clean canonical structures. Per-query deterministic seeds (derived from base_seed + noise_level + topology_index + query_index) ensure reproducibility despite classification methods consuming global RNG state.

189. **Grid-search weight optimization reveals modality informativeness hierarchy (c348)** - Equal weights (1:1:1) are suboptimal when modalities have different discriminative power. For path-vs-cycle classification, fingerprint alone achieves 70% while degree and spectral each achieve only 50%. Grid search over weight_resolution=5 produces 215 combinations and correctly identifies the optimal tuple. Key design: cached per-modality scoring precomputes degree/spectral/fingerprint scores once per query×reference pair, then evaluates all weight combos in O(combos × queries) without re-running classification. Tie-breaking by weight Shannon entropy prefers balanced weights when accuracy is equal. Completes the build → evaluate → **learn** → deploy loop.
190. **Confusion matrix with per-class metrics is the diagnostic instrument classification was missing (c349)** - Macro accuracy hides failure patterns. A full N×N confusion matrix with per-class precision/recall/F1 reveals WHICH classes are confused and HOW OFTEN. `most_confused_with` per class and `most_confused_pairs` globally provide actionable debugging targets. `hardest_queries` (queries where fewest methods succeed) identify outlier graphs that need investigation. The report works with all 8 classification methods and accepts user-provided (query, expected_label) pairs - unlike benchmark which auto-generates canonical topologies. This is the standard ML evaluation practice (scikit-learn's classification_report equivalent) that no graph library had.

196. **LOOCV for reference graphs tests "can we identify an UNSEEN topology?" - not just "how accurate are we?" (#046)** - Standard k-fold CV randomly partitions data. LOOCV for reference graphs has unique semantics: hold out one reference R_i, learn weights from remaining N-1, classify R_i. This directly tests whether the entropy fingerprint captures structural essence vs. memorizing specific reference instances. With 6 canonical topologies, it's 6 iterations (trivially cheap). The per-fold diagnostic ("held out 'path' → classified as 'star', gap=0.012") pinpoints exactly which structural features are insufficient. For amg: `classification_loocv()` = 17th classification API, ~30 lines.
197. **Graph distance scores are systematically under-confident - temperature T<1 needed (#046)** - ECE measurement reveals raw graph similarity scores (JSD, spectral, fingerprint L2) cluster in narrow bands, producing 52% ECE. Optimal temperature T=0.5 (sharpening). This mirrors the GNN calibration literature: GNNs are under-confident (Wang et al., 2021), unlike image classifiers which are over-confident. Root cause: graph distance metrics compress output space. Without normalization+temperature, raw scores can't be interpreted as probabilities. `classification_calibrate()` = 18th classification API: grid-search T to minimize ECE, return reliability diagram data. Makes all classification APIs' confidence values trustworthy for rejection thresholds.
198. **.632 bootstrap degenerates when apparent error is zero - which it always is for graph fingerprint matching (#046)** - The .632 correction assumes LOO error > apparent error. But graph entropy fingerprinting achieves 0% apparent error (exact match always identifies correct reference). So .632 = 0.368×0 + 0.632×loo_error = fixed 63.2% of LOO error. The adaptive property is lost - it becomes a constant shrinkage factor. Still useful (more conservative), but not bias-correcting in the intended sense. For honest reporting: use percentile bootstrap for n≥30, .632 as upper bound for n<30, and always report sample size alongside CI width.

201. **The recompute tax is the hidden cost of entropy-aware agent memory (#047)** - Every agent write changes graph topology. Without incremental entropy, each classification/retrieval/health check requires O(n3) full eigendecomposition. FINGER reduces this to O(Δn+Δm) - constant per edge update. At 1000 nodes, this is the difference between ~300ms blocking and <1ms streaming. Implication: entropy-aware features (24-API classification suite, entropy-weighted retrieval, TemporalEntropyTracker) can operate in real-time on streaming agent memory. No competitor (Mem0, Zep, Letta) has graph entropy at all, let alone streaming entropy. amg's entire 40+ entropy API surface becomes real-time-capable with ~200 lines of FINGER integration.
202. **Quadratic proxy Q is the universal O(1) graph health signal (#047)** - Q = 1 - tr(L2)/tr2(L) captures structural complexity in one number. High Q = diverse, well-distributed. Low Q = dominated by few nodes. Because Q updates in O(Δ) via Theorem 2, it serves as an O(1) real-time health monitor: every edge add/delete updates Q in constant time. The Q trajectory over time is a free graph health time series. Anomaly detection = "Q dropped >3σ from rolling mean." This extends entropy_explain's health layer from static snapshot to streaming monitor at zero additional computation cost.
203. **FINGER enables streaming anomaly detection - not just batch snapshots (#047)** - JS distance between consecutive graph states detects anomalous writes (contradiction bursts, injection attacks, topic shifts). Currently amg computes JS distance offline from snapshots. With FINGER incremental, each incoming batch produces a JS score in O(Δ). Write governance can reject batches with JS > θ before polluting the graph. Paper validated on Wikipedia networks (1.8M nodes) and DoS detection. Agent memory is smaller but higher-stakes - a rejected bad write is worth more than a detected anomaly.
204. **SLaQ and FINGER are complementary - different regimes (#047)** - SLaQ (stochastic Lanczos quadrature) for very large one-shot snapshots (n>105). FINGER for streaming sequences of incremental updates. Radial Projection for no-eigenvalue linear computation. Strategy for amg: exact eigendecomposition for small reference graphs (<200 nodes, classification suite), FINGER for streaming agent write path, SLaQ reserved for web-scale one-shot comparisons. Amg already has exact path (von_neumann_entropy); FINGER adds streaming path.

227. **Bi-temporal queries need 3 modes: knowledge, truth, certain (c412)** - What the agent believed at time T (knowledge) differs from what was objectively true (truth). The intersection (certain) is what the agent knew AND was correct. The classic Alice scenario: agent records Alice@Acme at T0, Alice moves at T1, agent discovers at T2. `bitemporal_as_of(T1+ε, mode="knowledge")` returns Acme (agent didn't know yet). `mode="truth"` returns Google. `mode="certain"` returns nothing (agent wrong). This trichotomy is absent from Mem0, Zep, Graphiti - they all conflate knowledge with truth. Named `bitemporal_as_of` to coexist with `query_as_of` (graph snapshot API).
