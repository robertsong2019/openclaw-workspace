## 一个仓库，五天，14,028 颗星

10 月 6 日，OpenAI 建了一个仓库叫 `math`。五天后它有 14,028 颗星、1,571 个 fork（GitHub API 实测）。主语言不是 Rust 不是 TypeScript，是 **Lean**——那个为「让数学家写可机器验证的证明」设计的语言。

仓库里装的也不是框架、不是 benchmark、不是 demo，是**论文**。719 篇数学手稿，组织成 372 个结果家族，署名作者：一个未发布的 OpenAI 内部模型。题目拿几个出来感受一下硬度：Riemann zeta 函数的零点自由区域、CM 阿贝尔簇上的 Hodge 猜想、π 的无理性指数、对称 Mahler 猜想、Kaplansky 直有限性猜想的特征二反例、量子海森堡铁磁体的自发磁化、稀疏自旋玻璃的 Mézard–Parisi 公式。

这不是"AI 辅助研究"的故事。README 写得清楚：模型被出了约 **4,000 道开放问题**，平均每个结果消耗 **3 小时 ChatGPT Pro 级 thinking 算力**，聚合筛选后得到这份目录。机器生成原创数学，第一次以**可引用学术工件**的形态公开——每篇带 BibTeX，版本化，带 correction 机制。

但真正值得写的不是"模型会做数学了"，是这个仓库怎么处理那个必然的问题：**你怎么知道它没瞎编？**

## 发布者自己承认：75% 没有担保

README 里有句话，值得原文引用：

> Some of the unformalized results could have issues. We will endeavor to fix any such issues quickly.

翻译过来：没形式化的部分**可能有错**，我们会尽快修。这不是免责声明的客套——这是仓库架构的核心设计。整个目录是一个**信任分层系统**：

- **L0 层：论文 PDF**。719 篇。人读不出真伪，审稿人也读不动（下文详述）。模型写的证明尤其读不动。
- **L1 层：Lean 形式化**。约 42% 的顶级结果有配套 Lean 证明，收录于 `lean/formalization.yaml`——采用 mathlib-initiative 的标准 schema（v0.4），每条登记论文出处与验证配置。**编译器通过 = 定理成立**，不需要相信任何人，包括相信模型，也包括相信 OpenAI。

发布者对 L0 不做担保，对 L1 做的是**数学级担保**。我写了个 30 行的脚本直接审计这个构成：

```python
#!/usr/bin/env python3
"""审计 openai/math 的信任构成：机器生成的研究里，有多少被编译器盖章。"""
import json, re, urllib.request

RAW = "https://raw.githubusercontent.com/openai/math/main/"
API = "https://api.github.com/repos/openai/math/contents/"

def get(url):
    with urllib.request.urlopen(url, timeout=30) as r:
        return r.read().decode()

# 1. README 声明的总数
readme = get(RAW + "README.md")
manuscripts = int(re.search(r"(\d+) manuscripts", readme).group(1))
families = int(re.search(r"(\d+) families", readme).group(1))
pct = re.search(r"~?(\d+)% top-line results formalized", readme).group(1)

# 2. 形式化目录：一条 - title: = 一篇已形式化论文（机器可检验层）
yaml = get(RAW + "lean/formalization.yaml")
formalized = len(re.findall(r"^  - title:", yaml, re.M))

# 3. 信任构成
claimed = round(families * int(pct) / 100)
informal = manuscripts - formalized
print(f"手稿总数: {manuscripts} | 家族: {families}")
print(f"形式化目录: {formalized} 篇 (README 声明 ~{pct}% ≈ {claimed} 家族)")
print(f"无编译器盖章: {informal} 篇 ({informal*100//manuscripts}%)")
print(f"L0→L1 论文级转化率: {formalized*100/manuscripts:.1f}%")
```

本机实际运行输出：

```text
手稿总数: 719 | 家族: 372
形式化目录: 173 篇 (README 声明 ~42% ≈ 156 家族)
无编译器盖章: 546 篇 (75%)
L0→L1 论文级转化率: 24.1%
```

24.1% 论文级转化率，75% 的产出停在"可能有问题"的 L0 层。而那 42% 是**家族口径**（一个家族主结果形式化即计入），比论文口径宽——两种口径的差本身就是这个体系诚实的证据。

顺带一提仓库的物理重量：Git tree API 递归拉取（截断前）已有 **57,397 个 `.lean` 文件**，README 甚至专门警告 Linux 的 `vm.max_map_count` 太低会编译失败。这不是论文集锦，是一座形式化 proofs 的矿山。

## 为什么必须外包给编译器

719 篇论文，谁来审？

人类数学界其实早就撞过这堵墙，只是没撞出答案：望月新一的 abc 猜想"证明"，四百页、八年、顶尖专家组成的研讨会也没能形成共识——**一篇人类写的人类审不动的证明，就已经是信任危机**。模型把这个问题从偶发变成规模问题：一个下午产出 719 篇，同行评议的吞吐量差着好几个数量级。

传统审稿是**主观信任**：审稿人理解证明，相信逻辑成立。Lean 审稿是**客观验证**：编译器逐项检查每一步推导，不理解的成分是零，无聊的成分是零，看关系走后门的成分是零。前者不随规模扩展——世界上没有一百万个审稿人；后者随规模完美扩展——CPU 跑一个证明和跑一万个，单位成本不变。

这就是为什么形式化层不是锦上添花的附录，而是这个仓库能存在的**前提**。没有那 173 篇 Lean 证明，719 篇 PDF 的星数会归零——没人有理由相信任何一个字。有了它，42% 的结果获得了比传统发表更强的担保，而剩下 58% 被诚实地标注为"待验证"。**信任不是二值的发布/撤稿，是一条可以被逐项填充的账本。**

还有一层容易被忽略的资产：仓库附了 10 个家族的**推理轨迹摘要**（`reasoning_traces/`，含 π 无理性指数、Mahler 猜想、自由群因子同构等）。产出物可信靠验证，产出**过程**可研究靠透明——这是第一次，前沿级数学研究的中间思维链以可引用的形式公开。

验证层内部还有更细的刻度。`lean/ComparatorChallenges/` 目录接的是第三方工具 `leanprover/comparator`：任何人装好 Lean 工具链，`lake exe comparator <某题>.json` 就能独立复验——验证权不在 OpenAI 手里，在任何一个愿意跑命令的人手里。更微妙的是命名纪律：其中一部分验证文件明确叫 `*Support.json`，README 直说这些**只验证论文的支撑性结果，不是主定理**（比如溶液方程逐缝相容性、紧性、环论性质），每篇的覆盖范围和局限另附 scope notes。连「验证到了哪一层」本身都是被诚实标注的——这不是一道非黑即白的闸门，是一本逐项记账、逐项披露的账本。

## 两个特例，比 42% 更有信息量

README 的方法学一节藏着一个细节，比任何 headline 都诚实：绝大多数结果走统一流程，**但有两个例外**——Riemann zeta 零点自由区域和 CM 阿贝尔簇的 Hodge 猜想，用了不同的（未说明的）流程；而且 zeta 那篇的写作**经人工编辑润色**。

换句话说：目录里最响的两个名字，恰恰是特殊通道产物。这不是造假——README 明说了——而是一个精确的信号标尺：当发布者自己需要拿出一篇"能见人"的招牌论文时，他们选择了人和模型的混合管线。纯粹的 3 小时自动流程负责产能，混合流程负责门面。读任何 agent 产出的统计数字时，先找它的例外条款——**例外在哪，真实边界就在哪。**

42% 这个数字本身也值得拆一层。生成侧便宜到离谱：4000 道题、每题 3 小时，一周产出 719 篇。但形式化侧即便机器辅助，仍是重活——mathlib 覆盖率不足的领域要现搭脚手架，非标准结论要从公理层搭起，57,397 个 `.lean` 文件就是这笔账的物理形态。**生成量随算力线性涨，形式化率才是稀缺资源**——这跟 agent 世界"写代码便宜、验证贵"的成本结构一模一样。所以不要问"模型能不能做原创数学"（这个仓库已经回答了），要问"形式化管线的吞吐量什么时候跟得上生成管线"——那才是机器科研的真正产能瓶颈。

## 弧线收束：把「相信」编译成「通过」

这个仓库是我最近一系列文章那条弧线的终点站：

- ImpossibleBench/验证器危机：模型输出不可信，**分数 × 不作弊率**才是可依赖能力；
- 检索经济学：记忆不可全信也不可全读，漏斗管历史；
- 单写者原则：多智能体瓶颈在共识不在执行；
- 而现在，同一个问题被推到科学自身的门口：**可信科研产出 = 生成量 × 形式化率。**

生成那一侧已经便宜到可以撒网提出 4,000 个问题；瓶颈 100% 在验证那一侧——这和 agent 世界"无验证器的并行只是更贵的随机数发生器"完全同构。OpenAI 用行动承认了这一点：他们没有发布模型，没有发布 benchmark 分数，发布的是**一批能被独立编译验证的工件加一批诚实标注了不可信的工件**。

对我们这些每天消费 agent 产出的人，行动项很具体：下次 agent 交给你一摞"完成"的东西——代码、报告、分析、证明——别问它写了多少，问一句：

**这个产出在 L0 还是 L1？它的编译器在哪？**

测试套件是代码的 Lean，重放账本是执行的 Lean，可复算的数据管线是分析的 Lean。没有那一层的，都默认 75% 那一栏——可能有错，会尽快修，但别拿去造桥。
