# 谁拥有那个数字？——一次正则放宽的毒理解剖

2026-09-18 · 信息抽取 · 评测工程 · 回归防护 · Python

## 放宽模式的真实成本，不是误报

修 bug 有两种爽法。第一种：定位精准，一行改动，测试由红转绿，全量回归干净——像外科手术。第二种：顺手多救了几道题，总分还在涨——像捡钱。

这篇文章讲的是一次两个都经历过的修复：前半程是干净的一行手术，后半程差点变成一场没人报案的谋杀。论点先放在这里——

**在「后命中者胜出」（latest-wins）的抽取系统里，放宽一个 pattern 的真实成本不是引入误报，而是静默杀死语料另一头已经正确的答案。这种谋杀在你的新测试里不可见，在总分里也不可见。**

## 现场一：序数后缀，一行干净手术

背景是我维护的离线评测管线：500 题的长程记忆基准，从几十万 token 的对话记录里抽取用户自述的属性作答。其中一族题问"我有几个项目"——counting/quantity 族。抽取器靠一组 pattern 匹配「数字 + 词干」的前向邻接，例如用户说 "I have 5 projects"，`5` 跟在陈述动词后面、挨着 projects 词干，命中，登记。

某天队列里一道题答错了：用户最新的自述是 "my 5th project"（我的第五个项目），金标期望答案是 5，管线却交出了 4——来自更早会话的一条旧陈述。简化后的病灶只有一行：

```python
# 数字-词干前向邻接（简化版）
STATED = re.compile(
    r"\b(\d+)\s*(projects?)\b"      # 期望 "5 projects"
)
# 真实语料: "just wrapped up my 5th project"
# 'th' 卡在 5 和 project 之间 → 邻接断裂 → s32 最新陈述不可见
# → latest-wins 落到 s4 的 '4' 上 → 答案错误
```

`5th` 的 `th` 后缀挡在数字和名词中间，前向邻接断裂，最新陈述整体不可见，latest-wins 逻辑滑向旧值。修复是加一个可选序数后缀：

```python
STATED = re.compile(
    r"\b(\d+)(?:st|nd|rd|th)?\s*(projects?)\b"   # "5th project" 也能锚住
)
```

红测试钉住这个 case，全量 replay 跑完：**恰好 1 个 diff，就是目标题**。干净收工。

## 诱惑：另一道 miss，和一个"合理"的放宽

还没庆祝完，队列里下一道题登场："close to 1300 now"——用户在陈述某个数量（1300），但语序是**词干在前、数字在后**，而 pattern 的前向窗只往后看。这不是 `th` 那种一字之差，是结构性的盲区：这个 pattern 无论怎么放宽后缀，都永远够不到数字在前的语序。

于是写了个 bare-quantity 分支：只要句子里有词干、有 now/current 这类现时性线索、且**恰好一个数字**，就认定这个数字属于该词干。逻辑讲得通：一个句子里只有一个候选数字和一个候选名词，还能是谁的？

```python
BARE = re.compile(r"\b(stem_word)\b[^.]*?\b(\d+)\b", re.I)
def maybe_bare(sentence):
    if NOW_CUE.search(sentence) and len(NUM.findall(sentence)) == 1:
        m = BARE.search(sentence)
        if m:
            return int(m.group(2))    # 句内唯一数字 → 归给词干？
```

单测绿了，目标题活了。如果是纯单测驱动的项目，到这里就提交了。

## Census：九个 diff，两个亡魂

但这条管线有一条铁律——**任何 pattern 改动，先建全量 diff 台账（census）再决定**：用新旧两版配置分别跑全量 500 题，逐 qid 比对预测值。census 本身朴素得不像纪律，更像笨功夫：

```python
def census(old_cfg, new_cfg, workload):
    diffs = {}
    for qid, ex in workload.items():
        was = run_extractor(ex, old_cfg)   # 旧版预测
        now_ = run_extractor(ex, new_cfg)  # 新版预测
        if was != now_:
            diffs[qid] = (was, now_, ex["gold"])
    kills = {q: d for q, d in diffs.items()
             if d[0] == d[2] and d[1] != d[2]}   # 旧版对→新版错
    assert not kills, f"banked kill: {kills}"   # 硬门，见下节
    return diffs
```

census 跑完，屏幕上是这个：

```text
ordinal-only:  1 diff   (a2f3aa27 '3'→'5')        ← 预期内，目标题
relaxed:       9 diffs  (含 1 个预期 + 8 个意外翻转)
```

九个。逐行验尸，两个是 **banked kill**——上一轮已经判定正确的题，这次被翻成了错的：

```text
46a3abf7: '3' → '20'   预测原正确，现错误
  原句: "I fill up my 20-gallon tank every 6 months..."
  词干命中，now-cue 命中，句内唯一数字是 20
  → bare 分支把 20 绑给了词干。金标是 3（别处的真陈述）

4b24c848: junk-CORRECT → '6'
  同款病理：数字属于 "6 months"，不属于词干
```

毒理图谱在这一刻显形：**自然语言的子句里，数字的主人有极大概率不是你以为的那个名词。** 抽样同族误命中，绑错对象琳琅满目——`20-gallon`（油箱容量）、`6 months`（时间间隔）、`2,000 miles`（保养里程）、`500 words`（文章篇幅）、`80D`（相机型号）。它们全都满足「词干在场 + 现时性线索 + 句内唯一数字」，全都不是答案。

"恰好一个数字所以归属无歧义"这个推理，在数学上成立，在语言学上是灾难。句子的信息密度分布决定了：数字几乎总是用来修饰**新引入的、更具体的**名词，而你要找的词干只是话题的锚。

## 回退，以及一扇单向门

结论无悬念：回退 relaxed 分支，只保留序数后缀修复。回退后 drift gate（全量 replay 的 pred 变更集必须恰等于预期集）满足——**恰 1 个 diff，正是目标题**。提交，banked 328→329，序列无回滚。

relaxed 分支没有消失，它进了台账，附带复活条件：下一轮若再攻这道题，需要的不是旧 pattern 的松弛，而是一个 **free-standing-digit 判别式**——数字必须自身游离于任何量词/单位/型号语境，才有资格被 bare 分支认领；且新判别式必须过全量 fire atlas 验证，两个 banked 行是硬门，一行都不许再倒。

复盘这个差点发生的事故，它有一个比「误报」更阴险的结构：latest-wins 系统里，**放宽是单向门**。你救的题在你的视野里（你为它写了红测试），你杀的题在语料另一头（没有任何测试覆盖它，因为上一轮它答对了，没人给对的题写测试）。总分还在涨——救活的新增分完全可能盖过杀掉的两个亡魂。没有 census，这次提交会以「净收益 +2」的姿态被合并，三个月后没人知道 46a3abf7 是怎么死的。

## 四条可以带走的纪律

这件事不只发生在评测管线。ETL 字段抽取、日志解析、特征工程——任何「pattern 命中即覆写」的系统都是同款毒理现场。四条纪律按执行顺序：

**1. census-first：先建全量 diff 台账，再决定去留。** 不要等出事再排查——diff census 要在决定「要不要这个改动」之前跑完。这次回退不是意志力胜利，是数据替我做的决定：`9 diffs vs 1 diff` 摆在一起，没有讨论空间。纪律的可执行性来自让正确选项显而易见。

**2. banked-kill 是硬门，不可协商。** 任何「已正确 → 错误」的翻转，自动否决整个改动，不进入收益权衡。理由很冷：你无法枚举被杀答案的下游成本，那就一律当无限大处理。

**3. 结构性盲区需要新判别式，不是旧 pattern 的松弛。** "close to 1300 now" 的语序盲区是结构性的——数字在词干前面，前向窗永远够不到。对结构性盲区的正确反应是发明 free-standing-digit 这种**新维度的证据**（数字自身的语境独立性），而不是把旧维度的阈值调松。后者救不回盲区，只会把看得见的区域搅浑。

**4. 死掉的方案要留下尸检报告和复活条件。** 回退不是终点：毒理图谱（数字常绑定的旁路名词清单）、两个 banked 行作为未来验证硬门、新判别式的形态——都写进台账。下一次有人（很可能是未来的自己）盯上这道题，第一件事是读尸检，而不是重新发明一遍 relaxed 分支、重新杀一遍 46a3abf7。

## 结语：谋杀的不可见性

测试工程的所有经典手段——红绿循环、覆盖率、突变测试——都在保护「你写下的意图」。但这次事故的病灶在意图之外：被杀的题在你的测试全集之外，在涨着的总分之内。**单测只会为你要救的东西作证，从来不为你要杀的东西验尸。**

在 pattern 覆写语义的系统里，唯一能让谋杀现形的工具是 census：新旧两版、全量语料、逐条 diff。它便宜（一轮离线跑）、粗暴、不优雅——和 CSI 的验尸报告一个性质。你不会每天都用，但每次放宽 pattern 之前，先问一句：

**这个数字，真的归那个名词吗？语料另一头，有没有人正在被我杀掉？**
