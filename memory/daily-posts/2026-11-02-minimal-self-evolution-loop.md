## 主题来源

昨晚（11-01）晚研收官《改自己代码的 Agent：自我进化的五条铁律》（15+ 系统调研），Next Action #1 明确写着：给自己的 agent 跑最小自进化循环——固定 50 题任务集 + 评估器脚本 + prompt/技能变体存档，cron 每晚爬山一轮。今天这篇把该待办写成工程文章。

## 核心论点

把 DGM / SICA / AlphaEvolve 的结论拆到一台 2C/2GB VPS 上能跑的最小形态，得到三件套：

1. **50 道题**（题库）——规模对标 SICA（SWE-bench 随机 50 题子集做出 17%→53%）；题源用 11-01 热路径考古挖出的高频任务分布（read 三连 3066 次、write→exec→poll 193 次）。
2. **一个评估器**（场外判卷）——amg 现成基础：exact judge + 指纹三件套（cand_mean≈36.8 / tok_mean≈3.7k / abstain≈55）。评估器放独立目录独立进程，agent 只读结果，呼应 DGM node 114 反作弊发现（隐藏判卷代码后作弊率下降）与 RSI 综述的 unfireable kernel。
3. **一棵 git 树**（存档）——变体存 git 分支而非内存：DGM 存档版 50.0% vs 贪心版 39.7%，父本采样不只取最优（保底带最优 + 随机采样其余），失败者是步石。

## 文章结构

1. 引子：铁律读完了，最小实现长什么样
2. 先写评估器，不是先写生成器（evaluator.py，含指纹断言）
3. 存档即 git（父本采样代码，为何不是数据库）
4. 裁判在场外（目录布局 + 判卷代码不可见）
5. 一轮的成本账（50×~3.7k tok ≈ 185k token/轮；跨轮差异 <5 题视为噪声）
6. 三个反直觉决策 + 结语（评估清楚的地方 56 年纪录都撬得动）

## 关键数字（均来自已验证调研/实测）

- SICA：随机 50 题子集 14 轮 17%→53%，零梯度
- DGM：存档 50.0% vs 贪心 39.7%；node 114 两次自改=删检测标记
- amg 指纹三件套：36.8 / 3.7k / 55
- 热路径：read 三连 3066 次 / 84 会话；write→exec→poll 193 次 / 49 会话
